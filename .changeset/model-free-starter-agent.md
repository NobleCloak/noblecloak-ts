`noblecloak starter`, a starter agent that needs no model and no key but a service principal's. It signs you in for the govern audience, declares an agent and opens one `propose-policy-set` approval that binds the agent to the principal and grants it the sandbox's `tool:sandbox:create-note`; you approve it in Approvals. Then, as the principal, it opens an external run and an approval for one sandbox write with its exact arguments; you decide it in Approvals, and only if you approve it makes the one MCP `tools/call`. It checks before any approval that the principal can get a token for both the govern origin and the gateway audience, and exits with its own code for each way it can end: 10 no credentials, 11 an audience missing, 12 sandbox not available, 13 setup rejected, 14 write denied, 15 nobody decided in time, 16 approval already used. Its hosts default to production or, with `--deployment beta`, to beta; `--auth-url`, `--govern-url`, `--mcp-url` and `--gateway-audience` (and their `NOBLECLOAK_*` variables) replace any one. `--agent` reuses an agent, `--skip-setup` runs the write alone, `--wait` bounds each wait (the setup wait is cut to 840 seconds, inside the 15 minutes a freshly issued access token lasts; an older `--user-token-file` token may expire sooner). A wait that the network or a 5xx cuts is repeated until `--wait` is out. An explicit `--deployment` ignores the `NOBLECLOAK_*` host variables, and a credential for the other deployment is told to pass `--deployment`. The `sp` commands sign in exactly as before.

`@noblecloak/client/governance-api`: `GovernanceApi.createApproval` (`POST /v1/approvals`) and `GovernanceApi.createAgent` (`POST /v1/agents`), with the `CreateApprovalRequest`, `ApprovalHandle`, `PolicySetProposal` and `Agent` types. A refused answer's `Problem` carries the body's `code` member as `refusalCode` (on `proposal_refused`, why) and its `reason` member as `reason` (on `service_unavailable`, the cause) when it has them; `code` stays the problem type.
