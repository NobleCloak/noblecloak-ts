'@noblecloak/cli': patch

`noblecloak sp rotate --credentials <path>` now reports an unreadable credential file the way `starter` does. Before: `--credentials <the raw argument> cannot be read.` Now: `Cannot read the --credentials file <absolute path>: no such file.` (or "permission denied", "it is a directory, not a file"), with a "Did you mean" for a near-miss `noblecloak-*.json` name. A relative path is resolved against the working directory, and the path is shown only when the argument looks like one: a token, a base64 secret, a URL or JSON given in its place is not printed. The other `sp rotate` and `sp create` messages that name a credential or output path (including the `--out` errors and the `credential <path>` lines) now show the absolute path with control characters (a newline in a file name too) escaped as `\uXXXX`. The `export NOBLECLOAK_SP_CREDENTIALS=<path>` line `sp create` prints is single-quoted for the shell when the path holds a character outside letters, digits and `_ . / @ % + , -` (so a `=` or `:` is quoted too: zsh expands `=cmd` and `~` after a `:`).

`@noblecloak/client/service-principal` exports `describeUnreadableFile(given, error, options)` and the types `DescribeUnreadableOptions` and `UnreadableFileDescription`: the function the loader and the CLI use for this message. The loader's messages are unchanged, except that the path rule now looks at the file name (the last segment) alone: a path with no extension, such as `/etc/noblecloak/credential`, or a directory such as `/work/sub`, is named when its directory exists, where before any such path of 16 or more characters was hidden as a possible token. A file name that is one unbroken run of 16 or more token characters with no extension is still hidden, and so is a bare name behind `./` or `../` (in a `key_file` too: it is judged against the credential file's directory) and a value with a backslash on POSIX, where a backslash is part of a name.
