Contract rev 17 (release `contract-v1-rev17`): **the `claude_agent_sdk` continuation kind**. `Continuation.kind` gains `claude_agent_sdk` for the Claude Agent SDK connector, which uses `delivery: pull`. Its `correlation` is documented as `{ session_id, tool_use_id, agent_id?, mode }` (`mode` `defer` or `retry`; a missing `agent_id` means the main agent) and stays opaque to the server, at most 8 KiB, echoed as sent. The seven existing kinds are unchanged and the enum stays closed: any other kind is still 400 `invalid_request`. The schema ties the new kind to `pull`: `claude_agent_sdk` with `push` or `held` is 400 `invalid_request`, and the seven earlier kinds keep every delivery. This is not a narrowing, because the kind did not exist before rev 17. `Capabilities` gains the optional member `continuation_kinds`, the continuation kinds the deployment accepts (items: the eight kinds of `Continuation.kind`), as rev 6 added `continuation_deliveries`: an adapter can read `capabilities()` at startup instead of learning from the first decision's 400. Unlike `continuation_deliveries`, where absent means all three, an absent `continuation_kinds` means the seven kinds of rev 16, because a deployment that predates rev 17 cannot advertise the member; a deployment that accepts `claude_agent_sdk` lists it. A kind the deployment does not accept is 400 `invalid_request`. The member changes conformance (skip rather than fail) and discoverability, nothing else on the wire. Later revisions that add a kind add it to the member's items.

A deployment that keeps its own list of kinds adds `claude_agent_sdk` and advertises `continuation_kinds` with it in the same change; until then it answers 400 `invalid_request` and skips the lifecycle scenario.

**Mock and conformance**

- The mock validates a request against the document's schemas, so it accepts and echoes the new kind and refuses an unknown one. The mock advertises `continuation_kinds` on either deployment wherever it serves approvals, as the `Continuation.kind` enum of the document it implements (the eight kinds on the committed document).
- Conformance: `continuation_kinds` joins the capability members a scenario may name in `advertises`, and the runner reads it from `GET /v1/capabilities`. A scenario may declare `serves_kind: <kind>`: it is skipped as a capability skip where `continuation_kinds` is advertised and lacks the kind, or is absent and the kind is not one of the seven of rev 16.
- New scenarios in `34-rev17-claude-agent-sdk.yaml`: `rev17-claude-agent-sdk-continuation-lifecycle` and the negatives `rev17-unknown-continuation-kind-is-refused` and `rev17-claude-agent-sdk-is-pull-only`. Each declares `serves_delivery` for the one delivery it sends (`pull`, `pull`, `held`), so a deployment that does not serve that delivery skips it. The lifecycle also declares `serves_kind: claude_agent_sdk`, so a deployment that has not adopted the kind skips it, and uses `mode: retry`. The two negatives are not gated on the kind: a deployment that has not adopted it passes both.
- `@noblecloak/client`: the generated `Continuation.kind` type gains `"claude_agent_sdk"`, and the generated `Capabilities` type gains `continuation_kinds?`.
